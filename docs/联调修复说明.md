# 前端联调修复说明

2026-09-20。`window.Siren` 的公开方法、状态名和事件载荷保持接口契约 v1.0 不变。

## 前端同步时间

- `melody:phraseStart` 的 `notes[].startMs` 始终从当句零点计算。示范音频默认在事件后约 80ms 开始，前端按这个提前量同步音块即可。
- 普通 `attempt:start` 后约 50ms 开始极短提示音；演唱采集与 `attempt:pitch.t` 从事件时刻计时。
- 节奏兜底每句也完整播放示范。其 RECORD 节拍固定在 `attempt:start + 500ms + note.startMs`，点击计时使用同一个 500ms 提前量。没有新增事件字段。
- 重听仍只在 `LEARN_LOOP / LISTEN` 有效，每句一次。重听先取消旧音频与旧倒计时排程，新的完整示范播完后才进入 COUNTDOWN。
- `ship:in` 已由后端按 `entryDelayMs` 错开发出，前端收到即入场，不要再重复等待这个延时。
- `FINALE` 回顾完整保留 25 个音的先后顺序，将音符总时长压至 3 秒；每音至少 100ms，其余时间按原时值分配。它是快速音乐回顾，不是原速重播。关闭此段长混响，约 3.18 秒后才到 RESULT，再过 400ms 到 SHARE_CARD。

## 已修复行为

- 首次进入就拒绝麦克风时，五句都沿节奏流程运行，不再错误读取未生成的普通旋律；终局使用这五句自己的 C4 音符。
- 每个节奏 RECORD 都发出一次 `attempt:end`；精准点击可引来完整 100 条船。
- RECORD 不再短暂广播 `subPhase: null`。
- 已有有效声音的短乐句，在目标结束后 600ms 完成，避免唱完后的等待被误判为无输入而清零。无输入仍在持续 3 秒时发出 `reason: 'silence'`，最长采集仍为 6 秒。
- 中止、重新初始化及再次开局会清理音频、录音流和旧定时器；重复点击开始不会叠加授权请求。旧授权异步返回的录音流会立即停止，不覆盖新一局。
- 最后一局录音结束后，进入 FINALE 时释放麦克风；RESULT 时清理余下音频。保留已解锁的 AudioContext 以供用户手势再次开局。
- 在事件监听器内同步调用 `abort()` 或 `init()` 也不会重新启动旧流程。

## 验证

`npm test` 和 `npm run verify` 均包含 `tools/test-lifecycle.mjs`。该测试为每个场景重新加载全部后端模块，覆盖冷启动拒权五句、播放与点击时序、重听、终局、无输入、短句完成、授权竞态、重新初始化，以及在多种同步事件中中止。使用虚拟麦克风的测试不能替代真机权限、扬声器串音与 WebView 性能验证。
