## 5. JS 兼容性说明

全量扫描 `game/**/*.js`，未发现超出 ES2017 的语法（无可选链 `?.`、空值合并 `??`、逻辑赋值、类字段、`Array.prototype.at`、`String.replaceAll`、`Object.hasOwn`、`structuredClone` 等）。

唯一命中的 `globalThis` 出现在 10 个模块的 UMD 包装中：

```js
})(typeof window !== 'undefined' ? window : globalThis);
```

`globalThis` 是 Chrome 71+，但在浏览器中 `typeof window !== 'undefined'` 恒为真，三元短路后 **`globalThis` 永不求值**，因此不构成兼容性问题。在 Node 下运行时才走该分支。

## 6. ⚠️ 已知未回退项：CSS Chrome 61（196 处）

**标记：CSS 兼容性未实测。** 本机无 Android 8.1 / Chrome 61 环境，下列结论来自静态扫描，**未经真机验证**。

`game/style.css` 的布局以 **Container Query 单位 `cqw`** 为核心：`.stage` 声明
`container-type: inline-size`，内部尺寸按 `Ncqw` 等比缩放。该能力晚于 Chrome 61，
在旧内核上单位无法解析、声明被静默丢弃（CSS 不像 JS 会抛异常）。

| 违规项 | 数量 | 引入版本 |
| --- | --- | --- |
| `cqw` 容器查询单位 | 112 | Chrome 105 |
| `clamp()` | 36 | Chrome 79 |
| flex `gap` | 28 | Chrome 84 |
| `aspect-ratio` | 8 | Chrome 88 |
| `min()` / `max()` | 8 | Chrome 79 |
| `dvh` | 2 | Chrome 108 |
| `container-type` | 2 | Chrome 105 |
| **合计** | **196** | |

**影响面**：`@media (orientation: portrait)` 与 `@media (max-height:460px) and (orientation:landscape)`
两个分支已用 px 覆盖主要交互元素，且都把 `.stage` 设为 `width:100%;height:100%`
（即移动端 `1cqw ≡ 1vw`），但**逐选择器覆盖不完整**——基础层中未被覆盖的声明在
Chrome 61 上仍会丢失，旧机型存在布局塌陷风险。

**决策**：本期按“现代机型优先”交付，未做 Chrome 61 基线重构。若后续需要兼容旧机型，
可行的增量路径是先做 `cqw → calc(var(--u) * N)` + JS 维护 `--u`（占 112/196，设计不变），
再处理 `clamp()` 分档、flex `gap` 的 margin 基线与布局行为检测、`aspect-ratio` 比例盒。
