## 1. 五条不可退让的设计原则

| # | 原则 | 落地要求 |
| --- | --- | --- |
| **P1** | **敢开口 > 唱得准** | 哼唱是一等公民，不设"哼唱模式"入口。首屏写「小声哼也行，她听得见」 |
| **P2** | **分数必须服人** | 四维打分**零随机**。唱成什么样就是什么样 |
| **P3** | **拉力必须被看见** | 船的位置变化要有情绪，不做纯数字进度条 |
| **P4** | **只回应，不评价** | **任何地方不得出现对玩家演唱的诊断**。玩家只能通过船的反应感知表现 |
| **P5** | **船数就是分数** | 不复用分数与船数两套标尺。玩家看到的数字只有一个：**N 条船** |

### P4 执行细则

- ❌ 不显示"音准 62 / 节奏 71"等维度拆解
- ❌ 不显示"第 3 个音低了"等定位提示
- ❌ 不显示"你跑调了""再大声一点""别害羞"等**祈使 / 评价句**
- ✅ 只显示：**船数**、**船的反应**、**海妖的反应**
- ✅ 唯一例外：**技术性异常提示**（麦克风没声音 / 周围有点吵）——设备反馈，非演唱评价

### P5 执行细则

- 分数与船数**是同一个数字**，不存在"总分 82，船 14 条"这种双标尺
- 单乐句结束时显示的是**本乐句新增触礁船数**
- 终局显示的是**累计触礁船数**（= 五乐句分数均值）

**目标用户**：18–28 岁女性，小红书重度用户，对互动内容有天然点击欲

**动机**：看到笔记"我的歌声吸引了 78 条船" → 想知道自己几条

## 5. 核心玩法

### 5.1 一句话规则

塞壬唱一段旋律 → 玩家模仿 → 四维打分（0–100，零随机）→ 分数决定**每条船被拽向礁石的概率** → 触礁船数计入战果。

### 5.2 单局结构：一首歌，5 个乐句

```
[进入] → 权限引导 → 5 秒无声演示
   ↓
┌────────── 乐句 i（i = 1..5）──────────┐
│ ① 听：海妖唱本乐句（3~7 音，可重听 1 次）  │
│ ② 备：呼吸倒计时 3-2-1，测环境噪音基线     │
│ ③ 唱：玩家模仿，音块按实时音高点亮         │
│ ④ 评：四维打分 → 本乐句分数（内部）        │
│ ⑤ 动：20 条新船入场，按分数逐船判定是否触礁  │
└───────────────────────────────────────┘
   ↓
[终局] 全曲回放 3 秒 →「你吸引了 N 条船」→ 分享卡
```

**为什么是"一首歌"而不是"5 次考试"**

叙事从"她考你 5 次"变成"**她教你唱完一整首歌**"。海妖从考官变成老师，情绪从竞技变成陪伴。5 个乐句拼成一首 8 小节小调，**终局能完整回放**，这是天然的分享素材。

### 5.3 旋律生成

| 项 | 规则 |
| --- | --- |
| 音阶 | **C 大调五声音阶**（C-D-E-G-A）。无半音冲突，跑调不刺耳 |
| 音域 | C4–C5；哼唱时算法自动八度折叠，不做提示 |
| 节拍 | **BPM 92 固定网格**，八分音符为最小单位 |
| 音色 | 三角波 / 加法合成 + 失谐堆叠 + 共振峰（详见 02 文档 D4） |
| 熟曲 | **50% 概率**抽取包内**公有领域**曲库的 3–7 音动机片段；歌名**结算后且分数 ≥ 60 才揭晓** |
| 原创曲 | 另 50%，种子 PRNG 生成 |
| 种子 | 编码进分享卡（"旋律 #4821"），**不联网也能做"同一段旋律挑战"** |

**难度曲线**

| 乐句 | 音数 | 特征 |
| --- | --- | --- |
| 1 | 3 | 级进为主，无跳进（建立信心） |
| 2 | 4 | 一个三度跳进 |
| 3 | 5 | 含一个五度跳进 |
| 4 | 6 | 节奏变化（加一个八分音符） |
| 5（Boss） | 7 | 大跳 + 最长句，海妖故意唱刁钻 |

> **Boss 回合的意义**：如果海妖全程希望玩家唱对，玩家永远玩不输，游戏没有张力。加"她在考验你"的设定后，**难度上升有了叙事理由**。

## 6. 评分模型（0–100，零随机）

| 维度 | 权重 | 算法 | 体感（内部参考，不展示） |
| --- | --- | --- | --- |
| **音型轮廓** Contour | **30%** | 相对音高方向序列（升 / 平 / 降）的编辑距离 | "调子走向对不对" |
| **音高准确** Pitch | **35%** | 每音取稳定段中位数 cents 偏差，±50 音分内满分，超出线性衰减 | "每个音准不准" |
| **节奏对齐** Rhythm | **25%** | 起音时刻偏差，DTW 对齐后减去中位数偏移 | "有没有跟上拍子" |
| **完整度** Completeness | **10%** | 漏音 / 多音惩罚；**奖励连续哼唱** | "唱完整了没" |

```
总分 = 100 × (0.30×Contour + 0.35×Pitch + 0.25×Rhythm + 0.10×Completeness)
```

### 6.1 三条防挫败规则（P2 落地）

1. **相对音高优先**：整体低八度、整体移调演唱**不扣分**。这是"哼唱也能满分"的数学基础。
2. **音色完全不进算法**：不看音量、颤音、气息。只有"音高序列 + 时间"参与计算。
3. **反馈前置替代事后诊断**（P4 的代价）：因为不给诊断，实时音块必须极其灵敏（**< 150ms**），让玩家在唱的当下就看见自己有没有对上。

## 7. 船队模型（船数 = 分数）

### 7.1 设计核心

```
乐句分数 score（0–100，四维，零随机）
      ↓
   拉力 pull（全局强度，逐船按敏感度 k 缩放）
      ↓
100 条船各自与阈值比较 → 触礁 / 停泊
      ↓
分母固定 100 → 期望触礁数 = 分数
      ↓
最终呈现：你吸引了 N 条船
```

### 7.2 船队编制

| 项 | 值 |
| --- | --- |
| 船队总规模 | **100 条**（分母固定，这是"船数 = 分数"的实现前提） |
| 波次 | 每乐句入场 **20 条**，5 波共 100 条 |
| 入场方式 | 每波 20 条从画面两侧与远景分批滑入（前端实现） |
| 停泊行为 | 未触礁的船留在海面漂浮，**不退场**（画面上"船越来越多"，本身就是奖励） |

### 7.3 核心公式

> ⚠️ **2026-09 决策：判定模型已从"阈值式"改为"线性映射"。**
> 原文为 `k ~ 截断正态(1.0, 0.24, 下限 0.35)` + `pull = score/100 × 1.5 × k` + `触礁 ⟺ pull > 0.8`。
> 该模型有两个无法修复的缺陷（实测数据见 `docs/规格问题清单.md` B1/B2）：
> - **低分段是死区**：中位船在 score < 53 时必然不触礁，score=20 → 一局 0 条船
> - **满分不满**：score=100 时仍有约 2.3% 的船逃掉（均值 97.7），满分拿不到 100 条，结局 A 几乎不可达
>
> 而"满分必全触礁"在 `pull > T` 形式下**数学上不可能**（k→0 时 pull→0，需 T ≤ 0；
> 而 T=0 会让任何正分数都全触礁）。故改为下面的线性式。

```
k_j  ~ Uniform(0, 1)                    // 每条船的"拉力敏感度"，有界
触礁 ⟺ k_j < score / 100                 // 线性映射
```

**由此得到的性质（全部可解析证明，已实测验证）**

- 单条船的触礁概率**恰好等于 `score / 100`** → 一局期望触礁数 **= 分数**（这才是"船数 = 分数"）
- `score = 0` → `k < 0` 恒不成立 → **必然 0 条**（连最低抗性的船也逃）
- `score = 100` → `k < 1` 恒成立 → **必然 100 条**（连最高抗性的船也留）
- 端点由**构造**保证，不是"大概率"——因此满分会稳定触发结局 A

**参数**

| 参数 | 值 | 说明 |
| --- | --- | --- |
| 船队总规模 | 100 | 固定分母，`FLEET_TOTAL` |
| 每波入场 | 20 | 5 波，`SHIPS_PER_PHRASE` |
| `k` 分布 | **Uniform(0, 1)** | 随机性的**唯一**来源 |
| 判定 | `k < score / 100` | 无阈值参数，触礁率即分数 |

> 旧参数 `LURE_GAIN` / `THRESHOLD_T` / `K_MEAN` / `K_SIGMA` **已全部删除**。
> ⚠️ **不要再引入"全局增益"** —— 加回增益会立刻打破"触礁率 = 分数"。
> 需要调难度请改判定曲线本身（`game/js/core/fleet.js` 的 `resolveWave`），
> 并用 `npm run curve` 查看改动后的完整曲线与结局分布。

**数值特征**

- **低分段不再有死区**：旧的 S 形模型里 20 分引不来任何船；现在 20 分稳定给 20 条。
  这对 PRD §12 的守门指标（"回合 1 ≥65 分"）尤其重要——新手的第一次尝试也能看到船进来。
- **进步感线性且可预期**：分数差 10 分，船数就差约 10 条。玩家能建立直觉。
- **两个端点有叙事重量**：0 分是"海面很干净"，100 分是"整片海面全是船"，两者都是**确定性**的。
- **随机性仍在**：同一分数下 1σ ≈ ±5 条（50 分处最大），"两个人都唱 62 分，一个 55 条一个 69 条"
  依然成立——随机性来自每船抽样，不来自分数。

### 7.5 关于"拉力敏感度的随机性"

**随机性只有一个来源：每条船各自的 `k`。**

| 项 | 是否随机 | 理由 |
| --- | --- | --- |
| 四维分数 `score` | ❌ **绝对不随机** | 唱成什么样就是什么样（P2） |
| 船只敏感度 `k` | ✅ 每条船独立抽样 | 制造"同分不同结果"的戏剧性 |
| 拉力公式 / 阈值 | ❌ 固定 | 避免"唱得好却输得莫名其妙" |
| 新船入场 | ❌ 固定 20 条 / 波 | 不做分数门槛（否则等于变相诊断） |

> **边界裁定：随机性只能加在"世界如何回应你"上，绝不能加在"你唱得怎么样"上。**
> 前者是惊喜，后者是背叛。
>
> **具体表现**：两个人都唱 62 分，一个吸引到 55 条，一个吸引到 69 条——这个差异**合理且有趣**，因为船本来就有大有小。
>
> **量化**（2026-09 按线性模型重测）：同一分数下，船数的 1σ 在 50 分处最大，约 **±5.1 条**
> （二项分布 `B(100, score/100)` 的固有波动）；两端收敛到 0（0 分与 100 分是确定性结果）。
> 实测各档标准差：10 分 ±3.05、30 分 ±4.67、50 分 ±5.08、70 分 ±4.56、90 分 ±3.01。
> **这是特性，不是缺陷。**

### 7.6 船只状态与视觉（P3 落地）

| 状态 | 触发 | 视觉（前端实现参考） |

| 游弋 | 刚入场 | 白帆像素小图，缓慢横向漂移 + 上下浮动 1–2px |

**海妖的情绪表达（不做任何文字提示）**

| 局面 | 她 |
| --- | --- |
| 本乐句拉力强 | 尾巴在水下的光亮增强，水面波纹向船队扩散 |
| 本乐句拉力弱 | 慢慢沉回水里，只剩眼睛露出水面 |
| 有船触礁 | 她多一分光 |
| 大量船触礁 | 海面整体亮起，水草摆动加快 |

### 7.7 结局

| 结局 | 条件 | 文案方向 |
| --- | --- | --- |
| **A｜全数触礁** | N = 100 | 海妖满意。"你把她的小把戏学会了" |
| **B｜船队大半沦陷** | N ≥ 70 | — |
| **C｜部分留住** | 20 ≤ N < 70 | "她在试着留住更多" |
| **D｜几乎都跑了** | N < 20 | "船走远了，她还在等你" |

> **内容安全**：全程童话像素风。无血迹、无尖叫、无恐怖元素。娱乐定性。

### 8.1 文案体系（P4 / P5 强制规范）

**只有一个数字：船数。禁用"共鸣度""评级""金句"三个词。**

| N | 主标题 | 海妖的一句话（**她的独白，不是给你的评价**） |
| --- | --- | --- |
| 100 | 全数触礁 | 她把你的声音记在了礁石上 |
| 85–99 | 船队失控 | 她有点惊讶，唱得更起劲了 |
| 60–84 | 大半落网 | 雾散了一半 |
| 30–59 | 只留住几条 | 她还在试 |
| 1–29 | 几乎都跑了 | 她有点怀疑，但还是唱了下去 |
| **0** | **一条也没留住** | **船走远了，她还在等你** |

> 最后一行是 P4 的收尾：**世界永远不责怪玩家。**

## 14. 最值得打磨的一个瞬间

**在最后一个乐句唱到 80 分以上时，20 条船成片涌向礁石，海面几乎被帆遮蔽。**

不靠任何数值提示，玩家自己就懂了：**我的声音把整支船队都引来了。**

那一刻玩家不会想"我得了 80 分"，他会想"**我还能再引来几条**"。
