## D3. 状态机

```
BOOT → HOME → PERM_REQUEST → (GRANTED) LEARN_LOOP
                            └ (DENIED) → RHYTHM_FALLBACK → FINALE

LEARN_LOOP (i = 0..4):
  LISTEN         海妖唱本乐句（可 replayPhrase() 1 次）
    ↓
  COUNTDOWN      3-2-1，同时采集 500ms 环境噪音基线
    ↓
  RECORD         采集 + 每 50ms 广播 pitch 事件；最长 6s，或静默 3s 中止
    ↓
  ANALYZE        切分 → 对齐 → 四维打分 → 只得到 score
    ↓
  PULL           生成 20 条新船 → 逐船判定 → 广播入场与触礁
    ↓
  PHRASE_RESULT  广播本乐句新增船数（1.5s）→ i++
    ↓
  i=5 → FINALE

FINALE → REPLAY(3s 全曲回放) → RESULT → SHARE_CARD → HOME
```

**约束**

- `RECORD` 必须由用户手势触发（否则 `getUserMedia` 被拒）。
- 静默 3s 中止时**不广播任何提示文案**，只广播 `attempt:end { reason: 'silence' }` 并把该乐句计 0 分。**让画面表达（海妖沉入水中），不用文字。**

### D4.1 AudioContext 解锁（iOS 关键）

  if (!ctx) ctx = new (window.AudioContext || window.webkitAudioContext)();
  if (ctx.state === 'suspended') await ctx.resume();   // 必须在用户手势内

### D4.2 音色合成（`siren` / `cue` / `tick` 三种）

**三层加法合成**

```js
// 第 1 层：谐波基线（≈三角波，柔和，音乐盒感）
const HARMONICS = [1, 0, 1/9, 0, 1/25, 0, 1/49];

// 第 2 层：失谐堆叠 —— "人声感"的最大来源
const DETUNE_CENTS = [-7, 0, +5, +9];
const DETUNE_GAIN  = [0.55, 1.0, 0.65, 0.4];
// 频率 = baseFreq * Math.pow(2, cents / 1200)
// 再给各层 8–25ms 延迟，模拟多人不同步

// 第 3 层：共振峰滤波（让"音"变成"人声"）
// 海妖角色：F1 = 500Hz (+6dB, Q=4) 串联 F2 = 1150Hz (+4dB, Q=6)
// → 介于 /o/ 与 /a/ 之间的开放元音，空灵但不阴森
```

| 角色 | 用途 | 设计目标 |
| --- | --- | --- |
| `siren` | 海妖唱旋律 | 人声感 + 童话感，旋律轮廓一耳听清 |
| `cue` | 玩家演唱时音块提示音 | **极短极干极中性**，绝不抢注意力 |
| `tick` | 节奏兜底节拍 | 干脆清楚 |

> ⚠️ **最常见的错误是用一个音色贯穿全场**。`siren` 和 `cue` 必须分开设计。

### D4.3 包络（最容易翻车的地方）

```js
env.gain.setValueAtTime(0, t);
env.gain.linearRampToValueAtTime(gain, t + 0.012);            // 12ms attack
env.gain.exponentialRampToValueAtTime(0.0001, t + duration);  // 指数衰减
```

| 参数 | 建议 |
| --- | --- |
| Attack | **10–20ms**（太短有"咔"声，太长听不出音头） |
| 衰减 | 指数，到 `duration` 结束 |
| **音符间隔** | **`duration = 时值 − 40ms`** ⚠️ |

> **最后一条必须做**：BPM 92 的八分音符是 326ms。若把 duration 设为 326ms 且无间隔，连续同音（如《小星星》开头两个 C）会糊成一个音，玩家根本不知道要唱两次。

### D4.4 颤音（可选但推荐）

| 参数 | 建议 |
| --- | --- |
| 速率 | 5.0–6.0 Hz |
| 深度 | 10–20 音分 |
| 起始 | 延迟 150ms 后淡入 |

> 颤音会轻微模糊音高，但判定取**稳定段中位数**，对称摆动不受影响。**安全。**

### D4.5 混响（不打包音频文件）

用 `ConvolverNode` + **代码生成的脉冲响应**：长度 1.6s，噪声 × `(1 − i/len)^2.8`，双声道。

- 混响链上串 `highpass @ 300Hz`（否则低频糊成一团）
- 干湿比 **干 70% / 湿 30%**，⚠️ **湿声绝不超过 40%**（会使音高轮廓模糊，损害旋律可识别性）
- IR **只在 AudioContext 创建后生成一次**

### D4.6 节拍网格

- BPM 92 → 四分 652.17ms，八分 326.09ms
- 所有音符的 `start` / `duration` 必须是八分音符整数倍
- `melody.js` 内部以"**八分音符格数**"为单位，不做自由时长

### D4.7 麦克风采集（三个 false 是全项目最重要的配置）

```js
const stream = await navigator.mediaDevices.getUserMedia({
  audio: {
    echoCancellation: false,   // 必须关：会吃掉人声
    noiseSuppression: false,   // 必须关：会破坏音高
    autoGainControl: false     // 必须关：动态压缩影响判定
  }
});
const src = ctx.createMediaStreamSource(stream);
const analyser = ctx.createAnalyser();
analyser.fftSize = 2048;
analyser.smoothingTimeConstant = 0;
src.connect(analyser);
// 绝不 connect 到 destination，否则啸叫
```

### D4.8 Web Audio 三个坑（必读）

1. **AudioParam 不可重用**：`OscillatorNode` 停止后不可重启。**用对象池**（预分配 32 个 voice，播完归还）。不做池化会在低端机上产生肉眼可见卡顿（GC）。
2. **别用多振荡器做失谐**：更省的替代是 **1 个振荡器 + 2–3 条 `DelayNode`**（8 / 16 / 24ms）。节点数从 4 个振荡器降到 1 个振荡器 + 3 个 delay。
3. **总输出必须限幅**：合唱段落（4 层失谐 + 混响）容易爆音。

```js
const limiter = ctx.createDynamicsCompressor();
limiter.threshold.value = -6; limiter.knee.value = 0; limiter.ratio.value = 20;
limiter.attack.value = 0.003; limiter.release.value = 0.1;
masterGain.connect(limiter); limiter.connect(ctx.destination);
```

## D5. 音高检测（`pitch.js`）

**选型**：简化 YIN（纯时域）。**不用 FFT 谱**——2048 点 @44.1kHz ≈ 21.5Hz/bin，C4 附近误差超 100 音分。

| 参数 | 值 |
| --- | --- |
| 采样率 | 运行时读 `ctx.sampleRate`，不硬编码 |
| 窗口 `W` | 2048 |
| τ 范围 | `[floor(sr/660), ceil(sr/90)]` |
| 检测间隔 | **50ms** |
| CMND 阈值 | 0.15 |
| 置信度门槛 | CMND 最小 < 0.30，否则视为无音高 |

**实现骨架**

```js
function detectPitch(buf, sr) {
  const W = 2048;
  const tauMin = Math.floor(sr / 660);
  const tauMax = Math.ceil(sr / 90);
  // yin 为模块作用域预分配的 Float32Array(tauMax + 1)

  // Step 1: 差分函数
  for (let tau = tauMin; tau <= tauMax; tau++) {
    let sum = 0;
    for (let i = 0; i < W - tauMax; i++) {
      const d = buf[i] - buf[i + tau];
      sum += d * d;
    }
    yin[tau] = sum;
  }

  // Step 2: 累积均值归一化差分 (CMND)
  yin[0] = 1;
  let running = 0;
  for (let tau = tauMin; tau <= tauMax; tau++) {
    running += yin[tau];
    yin[tau] = yin[tau] * (tau - tauMin + 1) / running;
  }

  // Step 3: 找第一个低于阈值的局部极小
  let tau = -1;
  for (let t = tauMin; t <= tauMax; t++) {
    if (yin[t] < 0.15) {
      while (t + 1 <= tauMax && yin[t + 1] < yin[t]) t++;
      tau = t; break;
    }
  }
  if (tau < 0) return { hz: 0, conf: 0 };

  // Step 4: 抛物线插值提升精度（必须，否则音分误差过大）
  const s0 = yin[tau - 1], s1 = yin[tau], s2 = yin[tau + 1];
  const denom = 2 * (2 * s1 - s2 - s0);
  const betterTau = tau + (denom !== 0 ? (s2 - s0) / denom : 0);

  return { hz: sr / betterTau, conf: 1 - s1 };
}
```

**实现要点**

- `Float32Array` **预分配在模块作用域**，检测循环内绝不 `new`
- **抛物线插值必须做**：不做时整数 τ 在 C5 附近造成 ±40 音分误差，直接吃掉 Pitch 容差
- 内层循环禁用闭包与 `Array.prototype` 方法

**性能预算**：单次 **< 5ms**。超预算 → 窗口降到 1024、间隔升到 80ms。**禁止引入 Worker（被禁）。**

## D6. 音符切分（`segment.js`）

| 规则 | 值 |
| --- | --- |
| 稳定音判定 | 连续 ≥ 100ms（2 帧）且 hz 波动 ≤ 60 音分 |
| 音高取值 | 该段 hz 的**中位数**（抗离群点） |
| 音符边界 | 相邻稳定段音高差 ≥ 80 音分 → 新音符；< 80 → 合并 |
| 碎片丢弃 | < 80ms 的丢弃 |
| 起音时刻 | 回溯到 RMS 能量上升沿 |

**哼唱特殊处理（关键）**：闭口哼唱无辅音起音，能量上升缓慢（50–150ms）。判定阈值改为"达到稳定能量的 **60%**"。**不做任何惩罚。**

## D7. 打分（`score.js`）— 接口已按 P4 收窄

### D7.1 对外接口

```js
// 唯一对外接口。绝不返回诊断信息，也绝不返回维度拆解。
window.Siren._scoreAttempt = function (target, actual) {
  const aligned = align(target, actual);                 // DTW
  const { offset } = computeTransposition(aligned);      // 八度折叠 + ±2 半音补偿上限
  const contour      = scoreContour(target, actual, aligned);
  const pitch        = scorePitch(target, actual, aligned, offset);
  const rhythm       = scoreRhythm(target, actual, aligned);
  const completeness = scoreCompleteness(target, actual, aligned);

  return {
    score: Math.round(100 * (
      0.30 * contour + 0.35 * pitch + 0.25 * rhythm + 0.10 * completeness
    ))
    // ⚠️ 不返回 contour/pitch/rhythm/completeness 的单独数值
    // ⚠️ 不返回任何话术字符串
    // 返回维度值会让"不诊断"形同虚设——UI 迟早会显示出来
  };
};
```

> **硬约束**：函数**只返回 `{ score }`**。不要为了"以后可能要用"而返回维度拆解——P4 是产品承诺，接口层面就要锁死。

### D7.2 全局移调补偿（P2 的数学基础）

```js
function computeTransposition(pairs) {
  const diffs = pairs.filter(p => p.actualIdx !== null)
    .map(p => actual[p.actualIdx].midi - target[p.targetIdx].midi);
  if (!diffs.length) return { offset: 0 };

  // 八度折叠到 [-6, +6] 半音
  const folded = diffs.map(d => { let x = d % 12; if (x > 6) x -= 12; if (x < -6) x += 12; return x; })
                      .sort((a, b) => a - b);
  const median = folded[Math.floor(folded.length / 2)];

  // 补偿上限 ±2 半音：超出部分不补偿，作为真实跑调计入 Pitch
  return { offset: Math.max(-2, Math.min(2, median)) };
}
```

> 玩家整体低八度（−12 半音）→ 折叠成 0 → **完全不扣分**。
> 玩家整体跑 5 个半音 → 只补偿 2 个 → 剩下 300 音分**如实扣分**。

### D7.3 四维算法

| 维度 | 实现 |
| --- | --- |
| Contour | 方向序列编辑距离；`Math.sign(Math.round(delta / 2))` 把微差归为"平" |
| Pitch | `CENTS_TOLERANT = 50` / `CENTS_ZERO = 200`，线性衰减；漏唱音记 0 分计入分母 |
| Rhythm | `RHYTHM_TOL = 120ms` / `RHYTHM_ZERO = 400ms`；**先减去中位数偏移**（允许整体慢半拍，只惩罚参差不齐） |
| Completeness | 命中率 − 多唱惩罚（`min(0.3, extra × 0.1)`，多唱宽容） |

- ❌ `generateDiagnosis()` 函数
- ❌ 任何话术模板表
- ❌ 单乐句诊断展示
- ❌ "最低维度"排序逻辑

const PENTATONIC_OFFSETS = [0, 2, 4, 7, 9];        // C D E G A

### D9.2 核心实现

```js
// 截断正态抽样（每条船的"拉力敏感度"）
function sampleK(rng) {
  let k;
  do {
    // Box-Muller
    const u1 = Math.max(rng(), 1e-9), u2 = rng();
    const z = Math.sqrt(-2 * Math.log(u1)) * Math.cos(2 * Math.PI * u2);
    k = CONFIG.K_MEAN + CONFIG.K_SIGMA * z;
  } while (k < CONFIG.K_MIN);
  return k;
}

// 生成一批新船
function spawnWave(rng, waveIndex) {
  const ships = [];
  for (let i = 0; i < CONFIG.SHIPS_PER_PHRASE; i++) {
    ships.push({
      id: nextId++,
      wave: waveIndex,
      k: sampleK(rng),
      wrecked: false,
      // 以下仅供前端布局参考，后端不关心如何画
      lane: i % 5,                    // 0..4，建议 5 条水平通道
      depth: rng(),                   // 0 = 近景，1 = 远景，前端据此缩放
      side: rng() < 0.5 ? 'left' : 'right',
      entryDelayMs: Math.floor(rng() * 600)
    });
  }
  return ships;
}

// 逐船判定（本乐句得分 → 本波触礁数）
function resolveWave(waveShips, score) {
  const base = (score / 100) * CONFIG.LURE_GAIN;
  let wreckedCount = 0;
  for (const ship of waveShips) {
    const pull = base * ship.k;
    if (pull > CONFIG.THRESHOLD_T) {
      ship.wrecked = true;
      wreckedCount++;
      emit('ship:in', { ship });        // 入场
      emit('ship:wrecked', { ship, pull });
    } else {
      emit('ship:in', { ship });        // 入场但停泊
    }
  }
  return wreckedCount;
}
```

### D9.3 为什么"期望触礁数 = 分数"（供 code review）

- 固定分母 100，每波 20，5 波
- `P(触礁) = P(k > T / ((score / 100) × 1.5))`
- 对 `k ~ 截断正态(1.0, 0.24)`，该概率与 `score / 100` 之间有 **±1.0 条 / 波**的偏差
- 5 波合计最大偏差约 **±1.0 条**（实测表见 `01-PRD.md` 7.4 节）
- **长期期望严格等于分数**；单局有 `1σ ≈ ±4.4` 条的自然波动

### D9.4 终局

const wreckedTotal = allShips.filter(s => s.wrecked).length;   // 0..100
// N = wreckedTotal → 广播「你吸引了 N 条船」

### D9.5 性能提示（非强制，但强烈建议）

- **每波 20 条分批入场**（避免一次性刷出 20 个精灵造成掉帧）
- **触礁后的船转为静态**（不再逐帧重绘）
- **停泊的船保留在海面**——画面上"船越来越多"本身就是奖励

## D11. 实时反馈通道（P4 下唯一的评分反馈，必须做到极致）

由于不给事后诊断，**实时音块是玩家唯一的自我校准手段**。

| 要求 | 指标 |
| --- | --- |
| 端到端延迟 | **< 150ms**（麦克风 → 检测 → 屏幕） |
| 广播频率 | **20Hz（每 50ms）** —— 前端可自行抽帧渲染 |
| 视觉映射（建议） | 音块按实时音高逐格点亮 |
| 颜色（建议） | 绿 = 准（±50 音分内）/ 黄 = 偏高 / 蓝 = 偏低 |
| 无声时 | 音块灰暗，**不显示任何文字** |

> **设计说明**：延迟超过 150ms 玩家就会觉得"系统在乱说"。P4 拿掉了事后诊断，等于把所有"让玩家信服"的责任压在这条实时通道上。**这是全项目最不能省性能的地方。**
