## 2. 画面结构

`#app > .stage` 是唯一舞台，`container-type: inline-size`，内部按 z 轴分层：

| 层 | 元素 | 说明 |
| --- | --- | --- |
| −3 | `.sea-scene` | 海景底图。横屏 `100% 100%` 铺满；竖屏 `auto 87%` 贴底，上方留出纯色天空放标题 |
| −2 | `.water-shimmer` | 纯 CSS 波光，渐变遮罩 + 缓慢平移 |
| 0 | `#fleet-canvas` | 船队。整舞台尺寸，`devicePixelRatio` 上限 2 |
| 2 | `.siren` | 海妖。图集 + 遮罩，三姿态靠 `background-position` 切换 |
| 6–18 | 各视图、音块条、船数、提示 | 普通 DOM |
| 30 | `.share-view` | 分享卡，展开时 `.stage` 整体 `visibility: hidden` |

海妖始终在 Canvas 之上（`.siren` 有 `z-index: 2`，Canvas 没有），所以船只会从她身后经过，不会盖住她。

## 3. 船队几何（横屏与竖屏是两套坐标）

所有位置都是舞台的比例值，集中在 `main.js` 的 `FLEET` 常量里，横竖屏各一套：

```js
FLEET.landscape  // 帆船带 y 0.285 起，停泊区 y 0.610 起，10 列
FLEET.portrait   // 帆船带 y 0.375 起，停泊区 y 0.452 起，15 列
```

必须分两套的原因是**海平线位置不同**：`sea.webp` 的海平线在图像高度的 0.266 处。横屏把整张图拉满舞台，海平线就落在 0.266；竖屏按 `auto 87%` 贴底，海平线被推到 `0.13 + 0.266 × 0.87 ≈ 0.361`。用同一组 y 值会让竖屏的船浮在天上。

竖屏还有第二个约束：海妖占据左下角，顶边在 y ≈ 0.613。停泊区最后一排在 y ≈ 0.605，**刚好压在这条线以上**，否则触礁的船会整片藏到她身后——而"船被拉过来"正是 PRD P3 要求必须被看见的那件事。改这两组数字前请先对照 §8 的截图复核。

竖屏终局把「再来一局 / 换一段旋律 / 分享卡」压到屏幕底部，中间的海面整片留给停泊的船队。

## 4. 素材接入方式

两张图集都**不是真透明 PNG**，必须与各自的遮罩配对使用（原因见 `docs/assets-generation.md`）：

- **海妖（DOM）**：`.siren-art` 同时设 `background-image` 与 `mask-image`，`background-size` / `mask-size` 都是 `300% 100%`，位置 `0% / 50% / 100%` 对应待机 / 唱歌 / 倾听，`mask-mode: luminance`。
- **船（Canvas）**：`compileSprites()` 在启动时把图集按三列切开，逐像素取遮罩的**亮度**写进 alpha 通道，再按有效像素裁边，得到三张离屏 canvas 精灵。之后每帧只是 `drawImage`，不再做像素运算。
- **降级**：任何一张图加载失败，`drawBoat()` 退回纯路径绘制的简笔船，游戏仍然可玩可结算。海妖图失败则只剩发光圈，不影响状态机。

字体 `siren-round.woff2` 由 `@font-face` 引入；`license.json` 按 OFL 要求随包分发，不被任何页面引用（打包校验已把授权文件排除在"冗余资源"提示之外）。

## 5. 接入后端的方式

```
renderState(state)        // 先用 getState() 画首帧
api.init()                // 再订阅 —— 订阅写在 init 之前，避免漏掉同步的 HOME 切换
```

14 个事件全部订阅，处理方式与契约 C3 一一对应。三条实现上的纪律：

1. **`ship:in` 收到即入场**。后端已按 `entryDelayMs` 错开发出，前端再等一次会翻倍延迟（见 `docs/联调修复说明.md`）。
2. **`attempt:pitch` 只改视觉**。音高只决定音块条上那颗珠子的高度，并做八度折叠；它不参与任何判定。
3. **状态码只做映射**。`NO_INPUT` 不出文字，改让海妖沉回水中；`STORAGE_FAILED` 不显示。

页面隐藏（`visibilitychange`）或离开（`pagehide`）时，前端主动调 `api.abort()` 并停掉 `requestAnimationFrame`，避免麦克风和音频在后台空转。

## 6. 动效清单

全部是 CSS 动画或 Canvas 逐帧，没有第三方动画库。`prefers-reduced-motion: reduce` 下，入场、漂浮、摇摆、闪光一律跳到终态。

| 动效 | 实现 |
| --- | --- |
| 海妖呼吸 / 发光 / 下潜 | `siren-breathe` 关键帧；`.is-glowing` 触礁时亮起；`.is-submerged` 用渐变遮罩沉入水面 |
| 船入场 | 从 `side` 侧滑入，850ms 三次方缓出 |
| 船漂浮 | 正弦位移 + 微小摇摆，频率按 id 错开 |
| 触礁 | 向停泊位平滑插值，同时缩小；到位后一次五道短闪光 |
| 音块条 | 播放时逐块点亮；录音时当前块按是否有声在亮 / 暗之间切换 |
| 倒计时 | 三个圆点依次点亮，不出数字 |
| 结算数字 | `result-pop` 位移 + 缩放淡入 |

## 7. 文案与硬约束的落地位置

- 全部中文文案写在 `main.js` 的 `labels` / `endingCopy` / `onTechnical` 三处，后端一个字都不给。
- 屏幕上任何时刻只有一个船数：`renderState()` 用 `phraseResult` 互斥地显示顶部计数与单句大字。
- 0 条船的结局文案是「船走远了，她还在等你」，不是失败提示。
- 没有评分、评级、音准/节奏拆解的任何入口；`tools/selfcheck.mjs` 第 6 项会扫描诊断话术关键词。

## 8. 验证方式与边界

`tools/test-ui.py`（需要 `playwright`，开发期工具，不进上传包）用真实 Chromium 跑两条完整路线：

```bash
node tools/serve.mjs 4173
python tools/test-ui.py --screenshots
```

- **fallback 路线**：真实拒绝麦克风权限，五句全部点拍完成。
- **microphone 路线**：注入合成的 Web Audio 媒体流按事件发布的音符发声，第 3 句故意不出声。

两条路线都断言：五次有序的 `phrase:result`、100 次 `ship:in`、船数三处一致、无外部请求、无控制台错误、桌面/横屏/竖屏三种视口下无横向溢出、无控件被裁、无破图、同屏不出现两个船数、无诊断话术。

**这些验证不能替代的部分**：真机麦克风与权限弹窗、扬声器串音、WebView 性能、真人演唱的分数手感、海妖合成音色的听感。这几项仍需按 README「无法在本机验证的部分」一节用真机与耳朵完成。
