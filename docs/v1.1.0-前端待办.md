## 1. 准备时间 = 1.5s（**会改到你现有代码**）

### 后端行为（已实测锁定）

```
海妖唱完 ──► COUNTDOWN 3 ──500ms──► 2 ──500ms──► 1 ──500ms──► RECORD 开录
                 └──────────────── 合计 1500ms ────────────────┘
```

`tools/test-integration.mjs` §4c 会校验"倒计时起点 = 海妖唱完那一刻，偏差 0ms"。
**如果前端按别的时长做动画，就会和后端录音起点错位。**

### 前端要改

- 倒计时**每档 500ms**（不是 700ms）。若用了 `later(..., 700)` 这类常量，改成 500。
- 倒计时只在 `subPhase === 'COUNTDOWN'` 期间跑，收到 `attempt:start` 立即收尾。
- 别自己计时驱动录音——录音起点完全由后端的 `attempt:start` 决定。

> ⚠️ 后端为了守住 1.5s，把 **500ms 噪音基线校准挪到倒计时窗口内并行执行**了
> （原来串行在倒计时之前，会把准备时间拖成 2s）。前端不需要知道这件事，
> 但如果发现倒计时期间有额外事件，那是正常的。

## 2. 新手引导关 `TUTORIAL`

### 状态机

```
HOME → PERM_REQUEST → 【TUTORIAL】 → LEARN_LOOP → … → FINALE → RESULT → SHARE_CARD
```

- 只在**首次游玩**出现（后端记 `siren.tutorialDone` 标记）
- `subPhase` 复用 `LISTEN` / `COUNTDOWN` / `RECORD`
- **`phraseIndex` 恒为 0**，不推进 → 前端不能用 `phraseIndex` 判断"第几句"
- 用 `phase === 'TUTORIAL'` 区分这是教学关

### 前端要做

| 项 | 说明 |
| --- | --- |
| 教学视图 | 和 `V2c` 主游戏视图同构即可，但要有教学文案/指示 |
| **跳过按钮** | 调 `Siren.skipTutorial()`，返回 `true` 表示真的跳过了（仅 `TUTORIAL` 阶段有效） |
| 船动画 | ✅ **必须有**：教学关也发 `ship:in` / `ship:wrecked`，让玩家看到"唱对 → 船触礁"的因果 |
| 歌名 | 教学乐句 `familiar === false`，不会揭晓歌名 |
| 结算 | 教学关**不发** `phrase:result`，不计入战果 |

### 教学关具体内容（后端固定，前端不用算）

- 3 个音，音级 `[0, 1, 0]`，时值 `[2, 2, 4]` 个八分格，五声音阶（原创，不是熟曲）
- 通过条件：至少 1 个音不是 `miss`
- 通过后自动进 `LEARN_LOOP`，`phraseIndex` 从 0 重新开始

## 3. 逐音档位反馈 `attempt:note`

玩家每唱完一个音，后端广播一次（一句 3–7 个音 → 每句 3–7 次）：

```js
{ index: 2, targetMidi: 67, actualMidi: 66.8, accuracy: 0.91, tier: 'great', t: 1304 }
```

| tier | 音分偏差 | 起音偏差 |
| --- | --- | --- |
| `perfect` | ≤ 50 | ≤ 150ms |
| `great` | ≤ 100 | ≤ 220ms |
| `good` | ≤ 200 | ≤ 400ms |
| `miss` | 其余，或漏音（`actualMidi === null`） | — |

**渲染建议**：探针沿音块滑动，滑到第 `index` 个音时弹出对应档位的颜色/图标/粒子。

### ⚠️ 三条红线（P4）

- ❌ **不要**做成文字诊断（"你这个音偏高了"）
- ❌ **不要**渲染"第 N 个音错了"这类定位文案 —— 那是 D7.4 明令禁止的诊断
- ❌ 结算页**仍然只有一个数字**：船数。不要暴露四维拆解

### 时序注意

`t` 单调递增，但**不保证与 `attempt:pitch` 严格交替**——前端不要假设两者的相对顺序。
末音在录音结束后才判，所以最后一个 `attempt:note` 会晚于最后一个 `attempt:pitch`。

## 4. 终局回放玩家录音 `player:replay`

`FINALE` 开始时广播一次，后端负责播放：

```js
{ durationMs: 11200, parts: [{ phraseIndex: 0, startMs: 0, durationMs: 2100 }, /* … */] }
```

### 产品规则（用户明确决策，必须遵守）

| 规则 | 说明 |
| --- | --- |
| **无缝衔接** | 句间留白已在后端去掉，`parts[]` 里 `startMs` 是**相对回放起点**的累计值 |
| **不允许跳过** | ❌ 前端**不要**渲染跳过按钮 |
| **超长自动加速** | 去留白后仍 > 15s → 后端按 **1.2 倍速**回放，`durationMs` 已是折算后的值 |
| 前端只做视觉 | 波形条 / 海妖倾听动画，用 `parts[]` 做分段高亮 |

### 边界情况（前端要能接住）

- **兜底模式（`RHYTHM_FALLBACK`）不发此事件** —— 没有录音，直接从 `FINALE` 进 `RESULT`
- **回放失败也不卡住** —— 后端若因环境原因放不出来，会**照常进 `RESULT`**。
  所以前端**不能**把 `player:replay` 当成"必然发生"，`RESULT` 可能紧随 `game:finale` 到来
- `melody:replay` 在终局**不再发出**（原"海妖全曲加速回放"已取消），前端可以取消订阅

## 6. 两版产物（过审版 / 完整版）

用户决策：**最新一版先不做摄像头，方便过审；摄像头的事下个版本再说。**

所以打包器已支持切出两版，前端按需取用：

```bash
npm run build          # 完整版 → dist/haixiao-minitool.zip
npm run build:review   # 过审版 → dist/haixiao-minitool-review.zip（切除全部摄像头代码）
```

| 版本 | 产物 | 用途 | 提审权限勾选 |
| --- | --- | --- | --- |
| 完整版 | `haixiao-minitool.zip` | 后续含摄像头时用 | 麦克风 + 本地存储（+ 摄像头，v1.2） |
| **过审版** | `haixiao-minitool-review.zip` | **本期提审** | **只勾麦克风 + 本地存储** |

### 本期（v1.1.0）实测

当前代码里**还没有任何摄像头代码**，所以两版产物**字节完全相同**
（签名 `sha256:eba7c821fec4`，1705KB）。等 v1.2 加了摄像头，两版才会真正分叉。

### v1.2 写摄像头代码时，前端必须遵守的切割约定

打包器用**成对标记**切除摄像头代码。**摄像头相关代码必须完整包在标记之间**：

```js
// CAMERA:BEGIN
async function startPipRecording() {
  var stream = await navigator.mediaDevices.getUserMedia({ video: { facingMode: 'user' } });
  /* …MediaRecorder / captureStream / drawImage… */
}
// CAMERA:END
```

**两道闸门会拦住打包**（已实测）：

| 情况 | 结果 |
| --- | --- |
| 标记外的游离摄像头调用（`getUserMedia({video:…})` / `MediaRecorder` / `captureStream`） | ❌ 报错终止，列出残留位置 |
| `CAMERA:BEGIN` 与 `CAMERA:END` 不配对 | ❌ 报错终止 |

也就是说：**别把摄像头调用散落在标记之外**，否则过审版打不出来。

### 摄像头形态（v1.2 参考，PRD §7.5.1.3）

```
getUserMedia(前置) → canvas 每帧绘制（游戏画面 + 眼嘴图层）
  → canvas.captureStream(fps) → MediaRecorder（Chrome 49+，基线安全）
  → Blob → FileReader.readAsDataURL → data:video/webm;base64
  → writeTempFile → { filePath }
  → saveImageToPhotosAlbum / postNote({ pageType:'video_publish' })
```

细节见契约 **C7**（端能力 JSBridge 规格，C7.1–C7.7）。

**关于"只抠眼睛和嘴巴"**：这是**画中画构图**，不是识别、不是生物特征提取，
不存在敏感信息处理问题——**在代码注释里写清楚即可**，不需要额外合规处理。
**不识别、不存储、不上传**，本地视频只在玩家主动分享时交给平台接口。

## 7. 🚨 待办与风险（不是后端的活，但会拦住上线）

### 7.1 CSS Chrome 61 未回退 —— **196 处**（优先级最高）

`game/style.css` 大量使用 `cqw`（112 处）、`clamp()`（36）、flex `gap`（28）、
`aspect-ratio`（8）、`min()/max()`（8）、`dvh`（2）、`container-type`（2）。

**基线是 Android 8.1 出厂 WebView = Chrome 61**，这些能力全部晚于 61，
旧内核上声明被**静默丢弃**（CSS 不抛异常），存在布局塌陷风险。

本期决策是"现代机型优先"，**未做基线重构**。若要兼容旧机型，增量路径：

1. `cqw` → `calc(var(--u) * N)` + JS 维护 `--u`（占 112/196，设计不变）
2. `clamp()` 分档
3. flex `gap` → margin 基线 + 布局行为检测
4. `aspect-ratio` → 比例盒

详见 `docs/发布校验记录.md` §6。

### 7.2 真机性能与听感全未实测

| 端到端延迟 | < 150ms | **未测** |
| 首屏时间 / 帧率 | — | **未测** |
