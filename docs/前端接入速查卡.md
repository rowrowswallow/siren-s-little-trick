# 前端接入速查卡（`window.Siren`）

> 配套 `03-接口契约.md`（权威定义）。本卡是**速查**：把联调时最常用的东西集中到一页。
> 契约与本卡冲突时，以契约为准；本卡另记录了实现侧的已知偏离（见 §7）。

后端不碰 DOM、不返回任何中文文案。你只跟 **8 个成员 + 14 个事件**打交道。

---

## 1. 接入骨架

```js
// ① 初始化（拿首帧状态 + 订阅事件）
Siren.init({ seed: 4821 }).then(function (state) {
  render(state);                       // 用快照画首帧
  Siren.on('state:change', onState);   // 之后靠事件驱动
  Siren.on('attempt:pitch', onPitch);
  // ...
});

// ② 开始游戏 —— 必须在用户手势里调！
btnStart.addEventListener('click', function () {
  Siren.start();
});
```

**必须在用户手势里调 `start()`。** 原因有两个，缺一不可：
- `AudioContext` 的解锁（否则海妖不发声）
- `getUserMedia` 的授权（否则麦克风被拒）

---

## 2. API（8 个成员）

| 成员 | 签名 | 说明 |
| --- | --- | --- |
| `init` | `(options?) → Promise<StateSnapshot>` | `options.seed` 固定旋律（**联调复现必用**）；`options.storagePrefix` 默认 `'siren.'` |
| `start` | `() → void` | HOME → PERM_REQUEST → 授权成功进 LEARN_LOOP，失败自动进 RHYTHM_FALLBACK |
| `replayPhrase` | `() → boolean` | 重听当前乐句。**每句限 1 次**；仅 `LEARN_LOOP` + `LISTEN` 阶段有效，否则返回 `false` |
| `abort` | `() → void` | 中止本局，回 HOME（同时释放麦克风与音频资源） |
| `on` | `(type, handler) → unsubscribe` | 返回**退订函数**，直接调用即可取消 |
| `off` | `(type, handler) → void` | 需传同一个函数引用 |
| `getState` | `() → StateSnapshot` | 同步快照，随时可读 |
| `version` | `'1.0.0'` | 字符串常量 |

**另外提供**（非契约，可选用）：

```js
Siren.capabilities  // { audioContext, getUserMedia, localStorage } 三个布尔值
```

用它做能力自检，例如进页面先判断能否走主流程。

## 3. StateSnapshot（`init()` 与 `getState()` 的返回值）

```js
{
  phase: 'LEARN_LOOP',     // 见 §4
  phraseIndex: 2,          // 0..4，当前第几个乐句
  totalPhrases: 5,         // 恒为 5
  subPhase: 'RECORD',      // LEARN_LOOP 内的阶段，见 §4；其它 phase 下可为 null
  shipsTotal: 100,         // 恒为 100（固定分母）
  shipsSpawned: 60,        // 已入场船数
  shipsWrecked: 41,        // ← 这就是"当前分数"，玩家唯一看到的数字
  seed: 4821               // 本局旋律种子，便于复现问题
}
```

## 4. 状态机

```
BOOT → HOME → PERM_REQUEST → LEARN_LOOP ─→ FINALE → RESULT → SHARE_CARD → HOME
                           └→ RHYTHM_FALLBACK ─┘
```

`LEARN_LOOP` 内部的 `subPhase` 循环（5 次）：

```
LISTEN（海妖唱）→ COUNTDOWN（3-2-1）→ RECORD（你唱）→ ANALYZE → PULL（船入场/触礁）→ PHRASE_RESULT
```

视图对照：

| 视图 | 对应 |
| --- | --- |
| V1 首页 | `HOME` |
| V2 授权引导 | `PERM_REQUEST` |
| V2b 节奏兜底 | `RHYTHM_FALLBACK` |
| V3 主游戏 | `LEARN_LOOP` + `LISTEN` / `COUNTDOWN` / `RECORD` |
| V4 单回合结算 | `LEARN_LOOP` + `PHRASE_RESULT` |
| V5 终局 | `FINALE` → `RESULT` |
| V6 分享卡 | `SHARE_CARD` |

> `subPhase` 在 `ANALYZE` / `PULL` 阶段可能极短（合并成一次 `state:change`），
> **不要依赖每个 subPhase 都必然到达**——用它是为了切换视图，不是为了做状态计数。

## 5. 事件表（14 个）

| 事件 | 载荷 | 你该做什么 |
| --- | --- | --- |
| `state:change` | `{ phase, subPhase, phraseIndex }` | **切视图**。最常用的事件 |
| `melody:phraseStart` | `{ phraseIndex, notes[], eighths[], familiar, seed }` | 海妖开口动画；按 `eighths` 高亮音块 |
| `melody:titleReveal` | `{ title }` | 揭晓歌名。**仅熟曲且该句 ≥60 分时才发**，可能整局都不发 |
| `attempt:countdown` | `{ from: 3 }` | 逐次下发 `3, 2, 1`（共 3 次） |
| `attempt:start` | `{ phraseIndex }` | 麦克风开始采集，音块进入待点亮态 |
| `attempt:pitch` | `{ t, midi, cents, conf, voiced }` | **每 50ms 一次**。实时音块点亮与配色 |
| `attempt:end` | `{ reason: 'done'\|'silence'\|'timeout' }` | 停止点亮。**`silence` 时不显示任何文字**（D3 硬要求） |
| `ship:in` | `{ id, lane, depth, side, entryDelayMs }` | 船入场。一条船一个事件，每波 20 个 |
| `ship:wrecked` | `{ id, pull }` | 该船滑向礁石 + 触礁闪光 |
| `phrase:result` | `{ phraseIndex, newWrecked, totalWrecked }` | V4：大字 `newWrecked` + 船队动画 |
| `game:finale` | `{ wreckedTotal, ending, seed }` | V5。`ending` ∈ `'A'\|'B'\|'C'\|'D'` |
| `melody:replay` | `{ notes[] }` | 终局全曲回放动画 |
| `notice` | `{ code, level: 'notice' }` | 见 §6 |
| `error` | `{ code, message }` | 见 §6 |

### `notes[]` 元素（三个事件共用）

```js
{ midi: 62, startMs: 0, durationMs: 326, degree: 1 }
```

后端只给 MIDI 与时值。**频率换算、音块配色、像素图选择全由你决定。**

### `attempt:pitch` 载荷

```js
{ t: 1234.5, midi: 64.3, cents: +18, conf: 0.86, voiced: true }
```

| 字段 | 说明 |
| --- | --- |
| `t` | 毫秒时间戳，**相对于 `attempt:start`**（不是绝对时间） |
| `midi` | 连续 MIDI（含小数），可直接映射到音块高度。`voiced=false` 时该值无意义 |
| `cents` | 相对最近半音的音分偏差，−50 ~ +50 |
| `conf` | 置信度 0–1 |
| `voiced` | **`false` 时把音块变灰暗，不要显示任何文字** |

> 后端保证 20Hz 推送（每 50ms）。你的渲染帧率可以更低，**自行抽帧**即可。

### `ship:in` 的视觉字段

| 字段 | 范围 | 建议用法 |
| --- | --- | --- |
| `lane` | 0–4 | 5 条水平通道 |
| `depth` | 0–1 | 0=近景 1=远景，建议映射缩放 0.6–1.0 |
| `side` | `'left'`/`'right'` | 从哪一侧滑入 |
| `entryDelayMs` | 0–599 | 错开入场时机；后端已按此延迟发出，你也可再错开 |

> 每波 20 条要**分批入场**，别一次性刷 20 个精灵。触礁后的船转静态，停泊的船可低频更新。

## 6. 状态码（`notice` / `error`）

**后端不返回中文**，你负责映射文案：

| code | level | 建议文案 |
| --- | --- | --- |
| `MIC_DENIED` | **error** | 如果您拒绝了麦克风权限，游戏就听不到您的声音咯 |
| `MIC_RETRY` | notice | 再点一下让她开口 |
| `NOISY_ENV` | notice | 周围有点吵，靠近一点麦克风 |
| `LOW_CONFIDENCE` | notice | 有点听不清，再靠近一点 |
| `NO_INPUT` | notice | **建议不显示文字，改让海妖沉回水中** |
| `STORAGE_FAILED` | notice | **建议不显示** |

**文案红线（P4/P5 强制）**

- ❌ 不得出现演唱诊断：「第 3 个音低了」「你跑调了」「再大声一点」「别害羞」
- ❌ 不得显示四维拆解（音准/节奏/轮廓分数）
- ✅ 只有一个数字：**船数**
- ✅ 0 条的文案必须正向：「船走远了，她还在等你」

## 8. 联调工具

```bash
npm run serve
```

| 页面 | 地址 | 用途 |
| --- | --- | --- |
| 入口 | `/` | 你的视图挂在这里（`game/index.html` 的 `#app`） |
| D14 试唱台 | `/js/lab/lab.html` | 试听音色 + 唱一句看分数与音高对比图。**联调时对照真值很有用** |
| M0 探针 | `/js/probe/probe.html` | 麦克风/性能/采样率体检 |

**这两个开发工具不进上传包**（`tools/pack.mjs` 自动排除 `js/probe`、`js/lab`）。

### 想复现某个 bug？

```js
Siren.init({ seed: 4821 })   // 固定种子 → 每局旋律完全相同
```

`getState().seed` 会返回本局种子，把它记下来就能复现玩家遇到的问题。

### 建议的开发顺序

1. 先只接 `state:change`，把 6 个视图骨架切起来（假数据也行）
2. 接 `melody:phraseStart` + `attempt:pitch`，做音块条与实时点亮
3. 接 `ship:in` / `ship:wrecked` / `phrase:result`，做船队
4. 接 `game:finale` + `melody:replay`，做终局
5. 最后接 6 个状态码的文案映射

## 9. 三个最容易踩的坑

**① 忘了在用户手势里调 `start()`**
表现：海妖没声音，或麦克风授权被直接拒绝。这是浏览器策略，不是 bug。

**② 在 `attempt:end` 的 `silence` 分支显示了文字**
D3 明确要求：静默中止**不广播任何提示文案**，让画面表达（海妖沉回水中）。
你收到 `reason: 'silence'` 时应该只做视觉反应。

**③ 想显示"第几个音低了"这类诊断**
D7.4 强制删除了它，后端也**不会返回维度拆解**。
玩家唯一的自我校准手段是 `attempt:pitch` 的实时音块（<150ms 延迟）。
如果觉得反馈不够，跟我说——但不要绕过契约自己推断维度分。
